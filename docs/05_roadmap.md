# 05. План: что пробовать дальше

Основание — [выводы журнала](04_experiments.md#выводы-на-0911). Надёжность решена; узкое место — качество ответов модели (Г7). Его мы ещё ни разу не видели своими глазами.

## P0. Прочитать реальные ответы модели (без сабмита, первым делом)

Без этого любой следующий сабмит — выстрел вслепую.

1. **Прогнать** `solution.py` на 18 демо-вопросах с настоящей моделью DeepSeek и включённой отладкой (`SOLUTION_DEBUG=1`). Как это сделать, описано в [тестировании](06_testing.md#прогон-на-настоящей-модели). У API DeepSeek нет эмбеддингов и реранкера, поэтому решение само перейдёт на BM25 — для оценки ответов это не важно.
2. **Положить** рядом вопрос, наш ответ и эталон из `demo_output.csv`. Для каждого вопроса отметить:
   - есть ли все ключевые элементы эталона: значение, документ и пункт, оговорка;
   - есть ли лишнее или выдуманное;
   - длину ответа;
   - сработала ли проверка чисел (`trimmed`, `repaired` в `debug.jsonl`).
3. **Свести потери** по типам вопросов из [таблицы типов](02_knowledge_base.md#типы-вопросов-и-правильная-реакция). Это и определит порядок экспериментов ниже.

Оговорка: публичный API DeepSeek (`deepseek-chat`) — не та же модель, что V4.1 Flash на платформе, а близкая. Типичные ошибки по стилю и логике она покажет, точный балл — нет.

## Очередь сабмитов

Одно изменение на сабмит. Порядок — по соотношению «ожидаемый эффект / риск / стоимость». После P0 порядок стоит пересмотреть.

| Код | Изменение | Гипотеза | Как поймём | Риск и цена |
|---|---|---|---|---|
| **К1** | Стартовый пример организаторов как есть | Калибровка: насколько baseline-подобное решение близко к нашему | Стартер ≈ 24–28 → наш конвейер почти ничего не добавляет, искать проблему в ответах; стартер заметно ниже → конвейер работает, дело в деталях | Тратит 1 сабмит, кода не требует |
| **К2** | Диагностика Г3: v1.3 без понижения режима при 4xx | Прокси принимает наш полный запрос (~10 тыс. токенов) | Ровно 20,77 → полный запрос отклоняется всегда, и v1.3 на платформе работает в урезанном режиме. Это важнейшая находка, и следующий шаг — ужать контекст. Между 20,77 и 24,65 → отклоняются только самые длинные запросы. Около 24,65 → полный режим работает | Тратит 1 сабмит. Делать, если P0 и К1 не объяснили слабость ответов |
| **X6** | Формат как у эталонов: 30–80 слов; прямой ответ → документ и пункт → одна оговорка; без смежных норм «на всякий случай» | Судья сравнивает с эталоном; лишнее размывает ответ и добавляет поводов для «выдуманного факта» | Балл выше 24,65 | Потеря полезной детали; дёшево — правка промпта |
| **X1** | Отдельный вызов анализа вопроса: самостоятельная формулировка, тип, дата события, утверждения пользователя для проверки, флаги (инъекция, давление, не по теме) → инструкция и примеры под тип | Больше побед на ловушках: редакции, ложные предпосылки, частичные ответы | Балл; в P0 — разбор по типам | +1 вызов на вопрос (~+50% времени); ошибка классификации портит ответ |
| **X3** | Защита от лишнего отказа: если модель ответила «в базе нет», а поиск нашёл сильный фрагмент, — второй вызов с указанием на этот фрагмент | Лишний отказ — поражение | Балл | Ответ там, где данных действительно нет |
| **X2** | Ответ в JSON с дословными цитатами; код проверяет, что цитаты есть в документах, а номера пунктов существуют | Меньше выдуманных пунктов и статей | Балл | Модель может не удержать JSON — нужен запасной путь |
| **X7** | Самопроверка: второй вызов «сверь каждое утверждение черновика с документами, исправь» на трудных типах | Меньше ошибок; кейс прямо предлагает такой этап, а эксперты оценивают «контроль достоверности» (25%) | Балл | Время; модель может «исправить» верное |
| **X4** | Расчёты в коде: неустойка, индексация, сроки | Нет арифметических ошибок | Балл | Таких вопросов мало |
| **X5** | Подсчёт частей статей ТК, чтобы ссылаться как эталон («часть первая ст. 59») | Ссылки ближе к эталону | Балл | Ошибка подсчёта даст неверную ссылку |
| **X8** | Больше законов в контексте: все статьи целиком (≈ 80 тыс. символов), кроме огромных ст. 164 и 284 НК (79 и 95 тыс. символов); из них — найденные пункты. Весь запрос ≈ 30 тыс. токенов вместо ~10 | Промахов поиска по законам не останется | Балл | Сильно зависит от Г3: если размер запроса ограничен, станет хуже; медленнее |

**Чего не делать:** несколько изменений в одном сабмите и подгонку под формулировки конкретных демо-вопросов (итог считается на private-вопросах).

## Подходы RAG: что взяли и что отклонили

| Подход | Решение | Почему |
|---|---|---|
| BM25 с морфологией | Взят | Юридический текст — точные термины и номера; основной сигнал |
| Плотный поиск bge-m3 | Взят | Ловит перефразировки («декрет» ↔ «беременность и роды») |
| Гибрид через RRF | Взят | Не требует калибровки весов двух шкал |
| Реранкер Qwen3 | Взят с ограничением по времени | Порядок среди законов точнее; зависать из-за него нельзя |
| Разбиение по структуре закона | Взято | Пункт — естественная единица ссылки; пометки редакций остаются при пункте |
| Заголовок документа и статьи в каждом фрагменте (contextual chunks) | Взято | Фрагмент «п. 3» без заголовка бесполезен и для поиска, и для модели |
| Документы компании целиком вместо поиска | Взято | Их мало; ловушки строятся на связях между документами |
| Расширение запроса словарём синонимов | Взято | Дёшево, закрывает сокращения: НДС, НДФЛ, МРОТ, главбух |
| BM25F (веса полей) | Отклонён | Аналог уже есть: заголовок в тексте фрагмента. Поиск по законам и так 20/20 |
| HyDE, multi-query | Отклонены | Лишний вызов модели при уже высокой полноте поиска |
| ColBERT, sparse-режим bge-m3 | Отклонены | Прокси отдаёт только плотные векторы |
| GraphRAG | Отклонён | Избыточно для 21 документа; связи документов решены проще (`related_docs`) |
| Готовый индекс эмбеддингов в архиве | Отклонён | Локально нет той же модели, а на платформе индекс строится за секунды |
| Локальный LLM-судья | Отклонён | Решение команды. Вместо него — P0: чтение ответов глазами рядом с эталоном |
| Дообучение модели | Невозможно | Модель фиксирована организаторами |

## Финальная сдача: что нужно кроме сабмитов

Из кейса ПСБ. Без этого команду не допустят к экспертной оценке.

### Веб-интерфейс чата (обязателен)
- Чат с ассистентом.
- Просмотр документов и фрагментов, которые подтверждают ответ. Ядро уже это знает: `debug.jsonl` содержит найденные пункты по каждому вопросу.
- Предлагаемый путь: вынести из `solution.py` функцию «вопрос → ответ + источники» и обернуть её в небольшой бэкенд (FastAPI) со статическим фронтендом. Веб-сервис должен использовать ту же модель, что и сабмит.

### Состав репозитория или ZIP
- Исходный код работающего решения.
- `README.md`: назначение и архитектура, одна команда запуска через Docker, переменные окружения, порты, зависимости, порядок проверки основного сценария, известные ограничения.
- `Dockerfile`, `compose.yaml`, `.dockerignore` — запуск всех компонентов одной командой.
- Файл зависимостей с зафиксированными версиями.
- `.env.example` без действующих ключей. Если используются внешние API, в README указать сервис, модель, имя переменной и порядок подключения ключа.
- PDF-презентация. На первом слайде — порядок проверки и ссылка на репозиторий, при наличии — ссылка на развёрнутый интерфейс. Дальше: проблема и пользователь, архитектура, сценарии, примеры ответов и отказов, ограничения, идеи развития.

### Доступ и секреты
- Репозиторий приватный: в нём материалы организаторов. Доступ выдать аккаунту жюри `hack-and-change-2026`.
- Никаких ключей и паролей ни в коде, ни в истории git, ни в материалах сдачи. После дедлайна версия фиксируется.

### На что смотрят эксперты (30% онлайн-этапа)
- **Контроль достоверности (25%)** — проверка чисел, отказы, редакции на дату, защита от инъекций. Это стоит показать в интерфейсе и презентации.
- **Работоспособность (20%).**
- **Архитектура и работа с документами (20%).**
- **Скорость (15%).**
- **Интерфейс (15%).**
- **Презентация (5%).**

В финале добавляется защита (30% итога). Больше всего весят ценность для бизнеса и качество ассистента в живой демонстрации — по 25%.

Дополнительные возможности, которые кейс предлагает явно:
- отдельный этап самопроверки ответа (X7);
- уточняющий вопрос, если неясно, о каком договоре, контрагенте или периоде речь (в сабмите сейчас — краткий ответ по всем подходящим договорам и просьба уточнить);
- последовательность шагов для процессных вопросов (согласование договора).
