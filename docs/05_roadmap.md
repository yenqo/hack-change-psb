# 05. План: что пробовать дальше

Обновлено 13.11.2026. Основание — [журнал сабмитов](04_experiments.md), [журнал экспериментов](../eval/experiments.md) и [бэклог](../eval/backlog.md).

## Где мы сейчас

- **Надёжность решена** (v1.3, B5–B8): модель отвечает на все вопросы, при сбоях прокси и нехватке времени решение понижает уровень обработки, а не сдаётся.
- **Главный прирост дал формат ответа:** B9 «строго на вопрос» — 25,7 → 43,8; B14 «ответ в формате эталона, без хвостов» — до 47,0 (сабмиты 15–16: 47,0 и 46,5). Судья — та же модель — считает «выдумкой» и верные детали, которых нет в эталоне.
- **Шум платформы — около 5 баллов** даже у одинаковых запросов, отправленных подряд (38,8–43,8). Эффекты меньше этого лидерборд не показывает.
- **Поиск — не узкое место:** на демо нужные документы и пункты в контексте в 51 из 51 ответа; почти все ошибки — генерации (лишнее, неполнота).
- **Golden set от продактов ещё нет.** До него — временный стенд на 18 демо-вопросах (парный замер) и целевые сценарии.

## Подходы RAG: что взяли и что отклонили

| Подход | Решение | Почему |
|---|---|---|
| BM25 с морфологией | Взят | Юридический текст — точные термины и номера; основной сигнал |
| Плотный поиск bge-m3 | Взят | Ловит перефразировки («декрет» ↔ «беременность и роды») |
| Гибрид через RRF | Взят | Не требует калибровки весов двух шкал |
| Реранкер (`cohere/rerank-5-fast` по умолчанию, модель задаёт платформа) | Взят, отключается временно при сбоях | Порядок среди законов точнее; зависать из-за него нельзя. Качество не измерено (на dev-стенде его нет) — B17 |
| Разбиение по структуре закона | Взято | Пункт — естественная единица ссылки; пометки редакций остаются при пункте |
| Заголовок документа и статьи в каждом фрагменте (contextual chunks) | Взято | Фрагмент «п. 3» без заголовка бесполезен и для поиска, и для модели |
| Документы компании целиком (parent-child в предельном виде) | Взято | Их мало; ловушки строятся на связях между документами. Для больших статей законов — идея B18 |
| Короткие статьи законов целиком | Взято | Статья до 7 000 символов из топ-4 поиска идёт целиком |
| Расширение запроса словарём синонимов | Взято | Дёшево, закрывает сокращения: НДС, НДФЛ, МРОТ, главбух |
| Переформулирование запроса (multi-query) | **Взято в облегчённом виде (R7)** | Только для диалогов и вопросов, которые поиск «не узнал»: вызов модели не на каждом вопросе; на платформе нейтрально |
| Few-shot на вымышленных документах | **Взято (7.6)** | Примеры на настоящих документах подсказывали модели готовые источники для похожих вопросов (Q18) |
| Выбор лучшего из нескольких ответов (best-of-N) | Отклонён (B15) | Офлайн: ни код, ни модель не выбирают лучший ответ стабильнее случая |
| Готовый индекс эмбеддингов в архиве | **Взят (7.2)** | Старт 27,9 → 2,6 с; контроль совпадения векторов с API |
| Расширение по отсылкам внутри законов | Реализовано (R6), в бэклоге | Цели отсылок поиск находит и так |
| Локальный LLM-судья | **Взят** для разработки (`tools/eval.py`) | Без него нельзя было увидеть, что судья наказывает за лишнее (B9) |
| HyDE | Отклонён | Лишний вызов модели при уже высокой полноте поиска |
| ColBERT, sparse-режим bge-m3 | Отклонены | Прокси отдаёт только плотные векторы |
| GraphRAG | Отклонён | Избыточно для 21 документа; связи документов решены проще (`related_docs`) |
| Дообучение модели | Невозможно | Модель фиксирована организаторами |

## Финальная сдача: что нужно кроме сабмитов

Из кейса ПСБ. Без этого команду не допустят к экспертной оценке.

### Веб-интерфейс чата (обязателен)
- Чат с ассистентом.
- Просмотр документов и фрагментов, которые подтверждают ответ. Ядро это отдаёт: цитаты со смещениями и поле `context` в ответе фасада ([integration.md](integration.md)).
- Веб-сервис использует то же ядро и ту же модель, что и сабмит (фасад `assistant.LegalAssistant`). Веб-часть делает отдельный разработчик.

### Состав репозитория или ZIP
- Исходный код работающего решения.
- `README.md`: назначение и архитектура, одна команда запуска через Docker, переменные окружения, порты, зависимости, порядок проверки основного сценария, известные ограничения.
- `Dockerfile`, `compose.yaml`, `.dockerignore` — запуск всех компонентов одной командой.
- Файл зависимостей с зафиксированными версиями.
- `.env.example` без действующих ключей. Если используются внешние API, в README указать сервис, модель, имя переменной и порядок подключения ключа.
- PDF-презентация. На первом слайде — порядок проверки и ссылка на репозиторий, при наличии — ссылка на развёрнутый интерфейс. Дальше: проблема и пользователь, архитектура, сценарии, примеры ответов и отказов, ограничения, идеи развития.

### Доступ и секреты
- Репозиторий приватный: в нём материалы организаторов. Доступ выдать аккаунту жюри `hack-and-change-2026`.
- Никаких ключей и паролей ни в коде, ни в истории git, ни в материалах сдачи. После дедлайна версия фиксируется.

### На что смотрят эксперты (30% онлайн-этапа)
- **Контроль достоверности (25%)** — проверка чисел кодом, отказы, редакции на дату, защита от инъекций. Это стоит показать в интерфейсе и презентации.
- **Работоспособность (20%).**
- **Архитектура и работа с документами (20%).**
- **Скорость (15%).**
- **Интерфейс (15%).**
- **Презентация (5%).**

В финале добавляется защита (30% итога). Больше всего весят ценность для бизнеса и качество ассистента в живой демонстрации — по 25%.

Дополнительные возможности, которые кейс предлагает явно:
- отдельный этап самопроверки ответа (сейчас — проверка чисел кодом, вызов исправления и обрезка лишнего после источника; выбор лучшего из нескольких ответов (B15) проверен и не дал эффекта);
- уточняющий вопрос, если неясно, о каком договоре, контрагенте или периоде речь (сейчас — краткий ответ по всем подходящим договорам и просьба уточнить);
- последовательность шагов для процессных вопросов (согласование договора; полнота — B11).
