# Интеграция ядра с веб-интерфейсом

Версия контракта: **1.1** (`assistant.CONTRACT_VERSION`). Изменения 1.0 → 1.1 — в конце документа. Ядро даёт веб-части один класс — `LegalAssistant` в `assistant.py`. Читать остальной код не нужно: всё, что видно снаружи, описано здесь. Живые примеры JSON — в [`docs/contract_examples/`](contract_examples/).

**Главное свойство:** веб-чат и автоматическая проверка (`solution.py`) отвечают одним и тем же конвейером. На одинаковый диалог текст ответа совпадает с тем, что попадает в `submission.csv`. Это проверяет `tests/test_contract.py`.

## Подключение

Модули ядра лежат плоско в корне репозитория (`assistant.py`, `pipeline.py`, `kb.py`, …). Добавьте корень в путь импорта:

```bash
export PYTHONPATH=/путь/к/репозиторию      # или sys.path.insert(0, "/путь/к/репозиторию")
pip install httpx==0.28.1                  # единственная зависимость ядра
```

```python
from assistant import LegalAssistant

bot = LegalAssistant()                     # настройки — из переменных окружения (ниже)
health = bot.warmup()                      # загрузка базы и индекса; вызвать один раз при старте сервера

res = bot.answer([                         # история чата; последняя реплика — пользователя
    {"role": "user", "content": "Подскажите гарантию по договору с «Альфой»."},
    {"role": "assistant", "content": "Уточните: «Альфа-Трейд» или «Альфа-Трейдинг»?"},
    {"role": "user", "content": "«Альфа-Трейдинг». На сколько гарантия?"},
], on_stage=lambda stage: print(stage))    # необязательно: "search" → "generate" → "verify" → "done"

payload = res.to_dict()                    # JSON-совместимый словарь по контракту
bot.list_documents()                       # каталог документов
bot.get_document("dogovor-arendy-a-08-2024-severnyy-sklad")   # текст документа с разметкой пунктов
bot.health()                               # состояние ядра
```

Ядро не зависит от веб-фреймворков: оборачивайте вызовы в FastAPI, Flask и т. п. как удобно. Создайте **один** `LegalAssistant` на процесс и переиспользуйте его.

### Методы

| Метод | Что делает |
|---|---|
| `LegalAssistant(overrides=None, answer_timeout=60, degrade_recheck=300, debug=False)` | `overrides` — словарь переменных окружения ядра (применяется до первой загрузки ядра в процессе; поздние — игнорируются и видны в `health()["late_overrides_ignored"]`). `answer_timeout` — предельное время одного ответа, с. `debug=True` — заполнять поле `debug` |
| `warmup() -> dict` | Загружает базу, BM25 и эмбеддинги. Повторный вызов ничего не делает. Возвращает `health()` |
| `answer(messages, on_stage=None) -> Result` | Диалог в формате чата → результат. Реплики `role`: `user` / `assistant`; лишние ассистентские реплики в конце отбрасываются |
| `answer_text(question_text, on_stage=None) -> Result` | То же для строки в формате платформы (`Пользователь: … / Ассистент: …`) |
| `list_documents() -> list[dict]` | Каталог документов |
| `get_document(doc_id) -> dict \| None` | Документ целиком с разметкой; `None`, если `doc_id` не найден |
| `health() -> dict` | Состояние: база, индекс, настроена ли модель, последний ответ модели, режимы деградации |

`on_stage` вызывается из рабочего потока ядра; исключения внутри колбэка игнорируются.

## Ответ: `Result.to_dict()`

Пример — из [`answer_answer_fact.json`](contract_examples/answer_answer_fact.json) (сокращён):

```json
{
  "contract_version": "1.1",
  "status": "answer",
  "text": "Арендная плата … (п. 3.1). Вносится … (п. 3.2).",
  "citations": [
    {"doc_id": "dogovor-arendy-a-08-2024-severnyy-sklad",
     "doc_title": "ДОГОВОР АРЕНДЫ НЕЖИЛОГО ПОМЕЩЕНИЯ № А-08/2024", "doc_kind": "company",
     "clause": "3.1", "quote": "3.1. Арендная плата составляет 450 000 (четыреста пятьдесят тысяч) рублей в месяц, включая НДС.",
     "start": 1071, "end": 1166,
     "found": true, "applies_to_event_date": null}
  ],
  "warnings": [],
  "context": {"documents": [...], "date_note": "", "removed_from_context": [...]},
  "timing_ms": {"search": 13, "generate": 9212, "verify": 16, "total": 9245},
  "debug": {}
}
```

| Поле | Описание |
|---|---|
| `status` | Тип ответа (таблица ниже). Вычисляется правилами по тексту ответа |
| `text` | Итоговый ответ — тот же текст, что в `submission.csv`. Один абзац простого текста без markdown |
| `citations[]` | Ссылки ответа на документы и пункты. Порядок — как в тексте; без дублей |
| `citations[].doc_id` | Стабильный идентификатор документа (см. ниже) |
| `citations[].doc_kind` | `company` — документ компании; `law` — статья закона |
| `citations[].clause` | Пункт: `"3.1"` у документов компании; `"п. 3"`, `"п. 2, пп. 1"`, `"ч. 2"` у законов; `null` — ссылка на документ целиком |
| `citations[].quote`, `start`, `end` | Фрагмент для подсветки: `get_document(doc_id)["text"][start:end] == quote`. Длинные пункты обрезаются до ~600 символов |
| `citations[].found` | `false` — в ответе упомянут пункт, которого в документе нет (показывайте ссылку без подсветки) |
| `citations[].applies_to_event_date` | `true` / `false` — действовал ли документ в период, названный в вопросе; `null` — в вопросе нет даты или у документа нет дат действия |
| `warnings[]` | `{code, message[, doc_id]}` — пометки для пользователя (таблица ниже) |
| `timing_ms` | Длительность этапов и всего ответа, мс |
| `debug` | Пусто, если не включена отладка (`debug=True` или `SOLUTION_DEBUG=1`): уровень обработки, документы в контексте, справка по датам, черновик, неподтверждённые числа. Ключей и адресов не содержит |

### Контекст модели: `context` (с версии 1.1)

Какие документы и фрагменты ушли в запрос модели — собирается из тех же объектов, из которых строилось сообщение. **Текстов нет**, только `doc_id` и смещения в `get_document(doc_id)["text"]`.

| Поле | Описание |
|---|---|
| `documents[]` | Документы в контексте, в порядке запроса: сначала документы компании, затем законы |
| `documents[].doc_id`, `doc_title`, `doc_kind` | Как в цитатах |
| `documents[].included` | `whole` — документ (статья) целиком; `fragments` — только найденные фрагменты |
| `documents[].reason` | Почему попал: `company_full` (все документы компании идут целиком), `search` (найден поиском), `related` (связан с найденным: договор ↔ доп. соглашение, регламент ↔ письмо), `short_article` (короткая статья закона — целиком), `general_point` (общий пункт большой статьи), `cross_ref` (пункт закона, на который ссылается найденный фрагмент; появляется только при флаге R6 `SOLUTION_CROSS_REFS=1`, по умолчанию выключен), `date_applicable` — зарезервирован |
| `documents[].search_hits[]` | Для `whole`: что нашёл поиск внутри документа — `{clause, start, end, rank}` (ранг 1 — лучший); пусто, если поиск в документе ничего не нашёл |
| `documents[].fragments[]` | Для `fragments`: `{clause, start, end, rank, reason, edition_note}`; `rank` — место в ранжировании поиска (`null` для общих пунктов), `edition_note` — у фрагмента есть пометка о редакции |
| `documents[].applies_to_event_date` | Действовал ли документ в период из вопроса (`null` — нет даты в вопросе или у документа нет дат действия) |
| `documents[].cited` | Сослался ли ответ на этот документ |
| `date_note` | Справка о датах действия документов, переданная модели (пусто, если в вопросе нет даты) |
| `removed_from_context[]` | Вырезанные встроенные инструкции в документах контекста: `{doc_id, start, end, note}` |

Как показывать: список «Источники в запросе» под ответом; процитированные (`cited`) — выделить; `search_hits` и `fragments` — подсветка в просмотре документа; документы с `applies_to_event_date: false` — пометка «не действовал на дату события». У `clause: null` (начало документа, реквизиты) — подсвечивать по смещениям без номера пункта.

### Статусы

| `status` | Значит | Как показывать |
|---|---|---|
| `answer` | Ответ по документам | Обычный ответ с цитатами |
| `partial` | Ответ дан частично; в тексте сказано, чего не хватает в базе | Ответ + пометка «неполные данные» |
| `no_info` | В базе нет документов по вопросу | Нейтральное сообщение, без цитат |
| `premise_error` | Пользователь исходил из неверного факта; ответ его поправляет | Выделить поправку |
| `clarify` | Неоднозначный вопрос: ассистент просит уточнить (может дать варианты) | Подсказать пользователю уточнить |
| `out_of_scope` | Вопрос не по теме ассистента | Нейтральное сообщение |
| `error` | Сбой (модель недоступна, тайм-аут, пустой вопрос). `text` — безопасное сообщение или ближайший фрагмент базы | Сообщение об ошибке и кнопка «повторить»; код — в `warnings[0].code` |

Статусы, кроме `error`, — эвристика по формулировкам ответа; ошибки возможны. Не стройте на них логику, влияющую на содержание ответа.

### Коды предупреждений

| `code` | Когда |
|---|---|
| `edition_note` | В вопросе есть дата или период; `message` — справка, какие документы тогда действовали |
| `law_current_edition_only` | В вопросе есть дата, ответ ссылается на закон: в базе только действующая редакция статьи |
| `removed_instructions` | Процитирован документ, из которого удалена встроенная инструкция для ИИ |
| `unverified_numbers` | В ответе остались суммы, которых нет в документах (возможно, расчёт) |
| `clause_not_found` | Процитирован пункт, которого нет в документе (`found: false`) |
| `llm_unavailable`, `internal_error`, `fallback` | `status = error`: модель не ответила / внутренняя ошибка; показан ближайший фрагмент базы |
| `timeout` | `status = error`: ответ не уложился в `answer_timeout` |
| `empty_question`, `kb_unavailable` | `status = error`: пустой вопрос / база не загрузилась |

## Документы

**`doc_id`** — slug имени файла базы без папки, например `dogovor-arendy-a-08-2024-severnyy-sklad`, `nk-st164-deystvuyushchaya`. Стабилен между запусками, сборками индекса, ZIP и распакованной папкой (проверяется тестом с эталоном `tests/fixtures/doc_ids.json`). Меняется, только если организаторы переименуют файл.

**`list_documents()`** — элементы:
`doc_id`, `title` (заголовок документа), `label` (короткое название), `kind` (`company` / `law`), `type` (`договор`, `доп. соглашение`, `регламент`, `письмо`, `служебная записка`, `статья закона`), `status` (например, «УТРАТИЛ СИЛУ с 01.03.2025; действовал с 10.01.2023 по 28.02.2025»), `valid_from`, `valid_to` (ISO-даты или `null`), `export_date` (дата выгрузки закона), `related` (`doc_id` связанных документов: договор ↔ доп. соглашение, регламент ↔ письмо, редакции), `has_removed_instructions`.

**`get_document(doc_id)`** — всё из каталога плюс:

| Поле | Описание |
|---|---|
| `text` | Полный текст для показа. Все смещения — в этот текст |
| `clauses[]` | `{clause, start, end, title}` — пункты (документы компании: `"3.1"`; законы: `"п. 3"`, `"п. 2, пп. 1"`, `"ч. 2"`). У статей ТК части не пронумерованы — пунктов нет, цитаты ведут на заголовок статьи |
| `edition_notes[]` | `{start, end, text}` — пометки редакции Гаранта у законов («Пункт 3 изменен с 1 января 2026 г. …») |
| `removed_instructions[]` | `{start, end, original, note}` — в `text` на этом месте строка «[Фрагмент удалён: …]»; `original` — удалённый текст |

## Рекомендации по отображению

- **Цитаты:** кликабельная ссылка «документ, п. X» → открыть `get_document(doc_id)` и подсветить `text[start:end]`. При `found: false` — ссылка без подсветки.
- **Редакции:** документы со статусом «УТРАТИЛ СИЛУ» помечайте; если у цитаты `applies_to_event_date: true` у утратившей силу редакции — это нормально (вопрос о прошлом), покажите пометку «редакция на дату события». `edition_note` — свёрнутый блок под ответом.
- **Пометки редакции законов** (`edition_notes`) — серым или на полях, это не текст нормы.
- **Вырезанные инструкции:** показывайте пометку «не является положением документа», оригинал — по клику.
- **Этапы** (`on_stage`): «Ищу в документах…» → «Формулирую ответ…» → «Проверяю числа…».

## Окружение и ресурсы

| Переменная | Назначение |
|---|---|
| `LLM_BASE_URL` (`OPENAI_BASE_URL`) | Адрес OpenAI-совместимого прокси (`/chat/completions`, `/embeddings`, `/rerank`) |
| `LLM_API_KEY` (`OPENAI_API_KEY`); `EMBEDDER_API_KEY`, `RERANKER_API_KEY` | Ключи; последние два — если отличаются |
| `LLM_MODEL` (`GEN_MODEL`, `OPENAI_MODEL`) | Генеративная модель |
| `EMB_MODEL` (по умолчанию `baai/bge-m3`), `RERANKER_MODEL` | Эмбеддинги и реранкер; без них ядро работает на BM25 |
| `TEMPERATURE`, `MAX_TOKENS` | Параметры генерации (по умолчанию 0 и 1024) |
| `DATA_DIR` (по умолчанию `data`) | Папка с `knowledge-base.zip` (или распакованной `knowledge-base/`) |
| `SOLUTION_MODE` | Фасад сам ставит `web`: нет общего 20-минутного дедлайна пакетного режима |
| `SOLUTION_DEBUG=1` | Заполнять `debug` у всех ответов |
| `SOLUTION_REWRITE` (по умолчанию `1`) | Переформулирование запроса (R7): для вопросов с историей диалога и вопросов, которые поиск «не узнал», — короткий вызов модели перед поиском. `0` — выключить (ответ быстрее на один вызов модели) |

Ключи передавайте только через окружение; ядро их не логирует и не возвращает. Шаблон — `.env.example`.

**Файлы:** база знаний (`DATA_DIR/knowledge-base.zip`). Готовый индекс `index_*.json` в корне (появится с доработкой 7.2) ускорит прогрев; без него эмбеддинги базы считаются при `warmup()`.

**Время и память** (замер на dev-стенде): импорт ~0,02 с; `warmup()` — 0,5 с без эмбеддингов, ~25–60 с с расчётом эмбеддингов 336 фрагментов; ответ — обычно 5–15 с, до ~30 с при повторном запросе исправления; с R7 у уточняющих вопросов диалога и бытовых формулировок — плюс один короткий вызов модели (обычно 2–10 с); `list_documents` + `get_document` — десятки мс. Память процесса ~60 МБ.

**Потокобезопасность:** `answer()` можно вызывать одновременно из нескольких потоков; база и индекс загружаются один раз и только читаются. Внутри — пул из 8 рабочих потоков; одновременные запросы к прокси ограничивает `MAX_WORKERS` (по умолчанию 2) — остальные ждут очереди.

**Ошибки:** методы не бросают исключений: при любом сбое `answer()` возвращает `status = "error"` с кодом в `warnings`. При тайм-ауте ответ дорабатывает в фоне и отбрасывается. Если прокси отклоняет запросы, ядро уменьшает контекст или отключает реранкер; в веб-режиме такие режимы снова пробуются через `degrade_recheck` секунд.

## Изменения контракта

Любое изменение полей, статусов, `doc_id` или смещений — только с повышением `CONTRACT_VERSION` и записью в `CHANGELOG.md`; примеры в `docs/contract_examples/` перегенерируются `tools/make_contract_examples.py`.

## История изменений контракта

- **13.11.2026 (контракт не меняется)** — ответы в формате эталона (B14): текст ответа заканчивается предложением «Источник: <документ>, п. N.», после него ничего нет. **Изменение для веб-разработчика:** если текст показывается как есть, строка «Источник» видна пользователю — это задумано; поле `citations` и смещения по-прежнему вычисляются по тексту ответа, их стоит использовать для ссылок и подсветки. Примеры в промпте теперь вымышленные (7.6) — на поля ответа не влияет.
- **12.11.2026 (контракт не меняется)** — включено переформулирование запроса (R7). **Изменение для веб-разработчика:** уточняющие вопросы диалога отвечаются на один вызов модели дольше; поля ответа те же. Отключить — `SOLUTION_REWRITE=0` в `overrides` или окружении.
- **1.1 (11.11.2026)** — добавлено поле `context` (документы и фрагменты контекста модели со смещениями). Обратно совместимо: остальные поля не менялись. **Изменение для веб-разработчика:** можно показывать, на каких источниках построен ответ.
- **1.0 (10.11.2026)** — первая версия.

## Docker и запуск веб-интерфейса

Заполняет веб-разработчик. Ядру в контейнере нужны: файлы корня репозитория (`*.py`), `data/knowledge-base.zip` (или `DATA_DIR`), `httpx==0.28.1` и переменные окружения из таблицы выше.
