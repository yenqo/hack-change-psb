# 06. Тестирование и проверки

Обновлено 13.11.2026. Логов платформа не показывает, поэтому решение проверяется локально на трёх уровнях:

- **без сети** — тесты, golden master, заглушка прокси, сбои и нагрузка в виртуальном времени;
- **с провайдером разработки** (ключ в `.env`) — прогоны на той же модели, что на платформе, и локальный LLM-судья;
- **перед сабмитом** — сборка архива и его запуск в чистом окружении.

Все инструменты — в `tools/` и `tests/` репозитория, только стандартная библиотека Python (+ `httpx` для ядра).

## Тесты без сети

```bash
tools/run_tests.sh            # на модулях в корне и на эталоне v1.3 (tools/baseline/solution_v1_3.py)
tools/run_tests.sh root       # только текущее ядро
```

Тесты на каждой цели, около 80 с:

| Набор | Что проверяет |
|---|---|
| `test_characterization.py` | Детерминированные части на реальной базе: разбор документов и законов, токенизация, синонимы, топ BM25, запасные ответы, разбор диалогов — совпадают с v1.3 |
| `test_golden_master.py` | 18 демо-вопросов через `main()` с заглушкой прокси в 7 сценариях (обычный, выдуманные числа, отказы 4xx, 429 и тайм-ауты, без эмбеддингов): тексты всех сообщений в модель и ответы — байт в байт как у v1.3 при выключенных флагах |
| `test_http.py` | HTTP-слой: повторы, 429, 4xx, разбор ответов (`httpx.MockTransport`) |
| `test_contract.py` | Контракт фасада для веба: JSON-схема, стабильность `doc_id`, смещения цитат и контекста, ответ фасада = пакетный режим, отсутствие исключений наружу |
| `test_web_mode.py` | Веб-режим фасада: включается, даже если ядро импортировано раньше; дедлайн запроса ограничивает ожидание модели; рабочий поток освобождается после тайм-аута |
| `test_prebuilt_index.py` | Готовый индекс: те же ответы с индексом, несовпадение векторов, чужая база, неожиданная ошибка — во всех случаях расчёт как в v1.3 |
| `test_docs_flags.py` | Каждая настройка `SOLUTION_*` ядра описана в README и есть в `.env.example` |
| `test_chunks_dump.py` | Служебная папка `eval/chunks/` и страница `eval/chunks/index.html` совпадают с текущей нарезкой `kb.py` (иначе — `tools/show_chunks.py --dump eval/chunks` и `--html eval/chunks/index.html`) |
| `test_pending.py` | Доработки за флагами (7.6, B3, 7.1, B5–B9, B12, B14, B14b, R6, R7, R7b, пакеты 1–2, B19–B20): что каждый флаг делает задуманное и не ломает прогон; B5–B8 — в виртуальном времени (`tests/simclock.py`) |

Новые флаги в тестах закреплены выключенными (`tests/harness.py`, `TEST_ENV`), поэтому golden master продолжает сравнивать с v1.3. Эталоны — `tests/fixtures/`; пересоздать с `tools/baseline/solution_v1_3.py` — `python tests/make_fixtures.py`.

Перед коммитом: `python tools/check_core.py` — импорты ядра (только stdlib и httpx), неопределённые имена, порядок зависимостей.

## Сбои и нагрузка (`tools/fault_eval.py`)

Прогоны на заглушке прокси в виртуальном времени — без токенов, за минуты:

```bash
.venv/bin/python tools/fault_eval.py --part resilience --configs "B5–B8,B5–B8+R7"
.venv/bin/python tools/fault_eval.py --part load
```

- **Сбои:** прокси ×2 и ×3 медленнее, разовые 400, смесь 400 + 429 + 503, таймауты и медленный реранкер.
- **Нагрузка:** 50 / 100 / 200 вопросов × 1 / 2 потока, прокси ×1 и ×2.
- **Метрики:** доля ответов на полном уровне, на пониженных, запасных; вызовов чата на вопрос; время прогона против бюджета 990 с.

Запускается после каждой доработки, меняющей ответы: устойчивость B5–B8 не должна пострадать. Результаты — в отчётах (`eval/reports/`).

## Заглушка прокси (`tools/stub_proxy.py`)

Детерминированные `/chat/completions`, `/embeddings`, `/rerank` без сети — для проверки архива и веб-части:

```bash
.venv/bin/python tools/stub_proxy.py --port 8765
LLM_BASE_URL=http://127.0.0.1:8765/v1 LLM_API_KEY=stub DATA_DIR=data .venv/bin/python solution.py
.venv/bin/python tools/ask.py --stub "Какая арендная плата?"
```

## Прогоны на модели (провайдер разработки)

`tools/dev_proxy.py` — локальный прокси: чат → провайдер из `.env` (DeepSeek V4.1 Flash, та же модель, что на платформе), эмбеддинги → локальная bge-m3 (ollama), реранкера нет (404). SQLite-кэш эмбеддингов и судьи; учёт токенов — `eval/token_ledger.csv`. Ключ никуда не выводится.

```bash
.venv/bin/python tools/eval.py --set smoke run --target current --label smoke_x --stage dev --judge
.venv/bin/python tools/eval.py --set smoke_org judge --label smoke_x --stage dev --tag _org   # эталоны организаторов
.venv/bin/python tools/ask.py --dev "Какая арендная плата?"
```

- **Наборы:** `smoke` — 18 демо-вопросов с эталонами задания, `smoke_org` — те же с эталонами организаторов, `golden` — набор продактов (когда появится), путь к CSV — целевые сценарии (`eval/scenarios/`).
- **Судья** — по регламенту платформы (попарно со стартовым примером, два порядка, «выдуманный факт = 0»); варианты j2 (мягкий) и j1 (строгий).
- **Временный стенд** до golden set — [eval/stand.md](../eval/stand.md): основная метрика — 10 вопросов вне few-shot; замер парный (без флага и с флагом поочерёдно в одной сессии).
- При сбое провайдера прогон и оценка не сохраняются (`*.failed.json`).

**Анализ сохранённых прогонов** (без вызовов модели): `tools/round2_compare.py` — сравнение с калибровкой или парное, сценарии с ключевыми элементами; `tools/diagnose.py` — ошибки поиска против генерации, лишнее, «Да/Нет»; `tools/answer_audit.py` — детали сверх эталона.

## Перед каждым сабмитом

1. `tools/run_tests.sh` — всё OK.
2. Если менялись ответы — парный замер на стенде и `tools/fault_eval.py`.
3. `tools/make_submission.py --stub-proxy` — архив `dist/psb_submission_<commit>.zip` собран и запущен в чистом venv; `--flag ИМЯ=ЗНАЧЕНИЕ` — значение флага по умолчанию только в архиве.
4. Строка в [журнале сабмитов](04_experiments.md#сабмиты): версия, одно изменение, гипотеза; после — балл, длительность и вывод; архив — в разделе «Архивы» описания коммита.
