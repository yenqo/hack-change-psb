# ПСБ: минимальный пример сабмита с тремя API

Это **учебный стартер**, а не готовое высокобалльное решение. Он показывает, как вызывать генеративную модель, эмбеддер и реранкер из кода, который запускается на платформе. Поиск максимально простой: сначала кандидаты выбираются по совпадению слов, затем короткие фрагменты ранжируются эмбеддером и реранкером. Для качества решения участники самостоятельно улучшают извлечение документов, разбиение на фрагменты, поиск и генерацию ответов.

## Состав архива

- `solution.py` — точка входа (создаёт `submission.csv`).
- `requirements.txt` — зависимость `httpx==0.28.1`.
- `README.md` — инструкция (можно не включать в финальный сабмит).

Файлы платформы: `data/questions.csv` (`id,question`), `data/kb.zip`. Для совместимости стартер понимает также `knowledge-base.zip` / `knowledge_base.zip`. База может содержать TXT, MD и DOCX.

## Три вида запросов

1. **Embeddings**: `POST {LLM_BASE_URL}/embeddings`, JSON: `{"model": EMB_MODEL, "input": ["текст 1", "текст 2"], "encoding_format": "float"}`. Возвращает векторы; они используются для приблизительного ранжирования документов.
2. **Rerank**: `POST {LLM_BASE_URL}/rerank`, JSON: `{"model": RERANKER_MODEL, "query": "вопрос", "documents": ["фрагмент 1", "фрагмент 2"], "top_n": RERANKER_TOP_N}`. Возвращает отсортированные индексы документов.
3. **Генерация**: `POST {LLM_BASE_URL}/chat/completions`, JSON: `{"model": LLM_MODEL, "messages": [...], "temperature": TEMPERATURE, "max_tokens": MAX_TOKENS}`.

Все запросы отправляются с заголовком `Authorization: Bearer <ключ из окружения>`. **Не вставляйте реальные ключи в исходный код, README или публичный репозиторий.**

## Переменные окружения

| Переменная | Использование |
|---|---|
| `DATA_DIR` | Путь к файлам задачи; обычно `data` |
| `LLM_BASE_URL` | Базовый адрес OpenAI-совместимого API; запасные имена `BASE_URL`, `OPENAI_BASE_URL` |
| `LLM_API_KEY` | Ключ генерации; запасное имя `OPENAI_API_KEY` |
| `EMBEDDER_API_KEY` | Ключ эмбеддера; при отсутствии используется `LLM_API_KEY` |
| `RERANKER_API_KEY` | Ключ реранкера, если предусмотрен; иначе используется `LLM_API_KEY` |
| `LLM_MODEL` | Генеративная модель; также читаются `GEN_MODEL`, `OPENAI_MODEL` |
| `EMB_MODEL` | Модель эмбеддингов; по умолчанию `baai/bge-m3` |
| `RERANKER_MODEL` | Реранкер; по умолчанию `cohere/rerank-5-fast` |
| `TOP_K` | Сколько кандидатов взять простым поиском перед эмбеддером |
| `RERANKER_TOP_N` | Сколько документов оставить после реранкера |
| `CHUNKER` | Пример настройки разбиения: `common` обрезает начальный фрагмент по границе строки, если возможно; иной режим просто обрезает по длине |
| `TEMPERATURE` | Температура генерации |
| `MAX_TOKENS` | Лимит токенов генерации |
| `MAX_WORKERS` | Число одновременно обрабатываемых вопросов |

`PYTHONPATH` управляет поиском модулей Python и обычно не требует обработки внутри `solution.py`.

## Что важно

- Для входного файла `questions.csv` заголовок — `id,question`.
- Выходной `submission.csv` содержит `id,answer`, каждое поле в двойных кавычках, по одной строке на ID.
- При ошибке эмбеддера или реранкера пример не прерывает выполнение, а использует упрощённый поиск. Смотрите stderr в логах платформы.
- Это базовый пример вызовов трёх моделей; результаты и качество не гарантированы.
